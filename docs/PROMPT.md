# Как запускать

## Подготовка (один раз)
1. Создай пустую папку проекта, например `svoimi`, и выполни в ней `git init`.
2. Положи `CLAUDE.md` в корень, а папку `docs/` (SPEC.md, DESIGN.md, PLAN.md) рядом с ним.
3. Запусти Claude Code в этой папке.
4. Подключи скилл frontend-design: введи `/plugin`, найди frontend-design в официальном каталоге Anthropic и установи. Если не найдётся, ничего страшного: главное из него уже перенесено в DESIGN.md.
5. Включи plan mode (Shift+Tab), чтобы первый ответ был планом, а не кодом.

## Промпт 1 (старт)
```
Делаем MVP веб-сервиса «Своими словами». Вся спецификация лежит в репозитории: CLAUDE.md (правила), docs/PLAN.md (фазы), docs/SPEC.md (продукт), docs/DESIGN.md (дизайн).

1. Прочитай CLAUDE.md и docs/PLAN.md. SPEC.md и DESIGN.md прочитай целиком один раз сейчас, дальше по фазам читай только указанные разделы.
2. Для всех UI-фаз используй скилл frontend-design, если он доступен. При расхождениях приоритет у DESIGN.md.
3. Пока не пиши код. Перечисли до 5 неясностей или противоречий в спецификации и по каждой предложи решение. Дождись моего «ок».
4. После «ок» выполни фазы 0 и 1 и остановись с отчётом по правилам из CLAUDE.md. Отдельно выведи, как пример из Приложения A SPEC разбился на блоки и какие ключевые фразы выделились у каждого.
```

## Промпт для следующих фаз
Перед каждой фазой сделай `/clear`, чтобы не тащить контекст и не тратить лимиты.
```
Прочитай CLAUDE.md и docs/PLAN.md. Выполни следующую неотмеченную фазу. Читай только разделы SPEC и DESIGN, указанные в этой фазе. В конце сделай отчёт по правилам CLAUDE.md.
```

## Если что-то не нравится
```
Фаза N, правка: <что не так, что ожидал>. Поправь, не трогая остальное. Если правка противоречит SPEC или DESIGN, сначала обнови документ, потом код.
```
