# PLAN: фазы MVP

Правило: одна фаза = одна сессия. Читай только разделы, указанные в фазе. В конце фазы: build, test и lint зелёные, отметь `[x]`, сделай коммит и дай отчёт.

## [x] Фаза 0. Каркас
Читать: CLAUDE.md, DESIGN §2–3.
- Vite + React + TS strict, Tailwind v4, ESLint, Vitest.
- `tokens.css` с тремя темами, `fonts.css`, атрибут `data-theme` на `<html>`, временный переключатель тем.
- Навигация между экранами через состояние в Zustand (`screen: 'home' | 'split' | 'session' | 'result'`), без роутера.
- Тест контраста токенов (WCAG, DESIGN §2).

Готово, когда: `npm run dev` показывает пустой экран в нужной теме и шрифтах, три темы переключаются, тест контраста проходит.

## [x] Фаза 1. Логика
Читать: SPEC §5, §6, §7, §9 (формула «Свои слова»).
- `segment.ts`, `keywords.ts`, `stem.ts`, `stopwords.ts`, `metrics.ts`, `pressure.ts`.
- Тесты на все случаи из SPEC §6 и §12, на ключевые фразы для текста из Приложения A, на давление с подставным временем.

Готово, когда: не меньше 40 осмысленных тестов проходят, разбивка Приложения A при пресете medium выглядит разумно (выведи её в отчёт).

## [x] Фаза 2. Данные
Читать: SPEC §4, §10 (резервная копия).
- Dexie-схема, Zustand-стор, автосохранение, `backup.ts` с тестами.

Готово, когда: документ переживает перезагрузку, резервная копия выгружается и загружается обратно.

## [x] Фаза 3. Home и импорт
Читать: SPEC §3.1, §10 (импорт), DESIGN §5 Home, §7.
Готово, когда: вставка, файлы .txt, .md, .docx и пример текста создают документ, список документов работает.

## [x] Фаза 4. Split
Читать: SPEC §3.2, DESIGN §5 Split, §6.2.
Готово, когда: склейка, разрез, правка ключевых фраз и смена пресета работают, ручные правки сохраняются.

## [x] Фаза 5. Сессия и растворение
Читать: SPEC §3.3, §3.5, §8, DESIGN §4, §5 Session, §6.1, §6.6.
Готово, когда: документ проходится от начала до конца одной клавиатурой, растворение соответствует спеке, вставка заблокирована, счётчики typed и pasted работают.

## [x] Фаза 6. Подсказки
Читать: SPEC §3.4, §3.5, DESIGN §6.2–6.4.
Готово, когда: все 4 ступени работают с клавиатуры и мышью, статистика пишется, в DOM скелета нет скрытых слов (проверь тестом).

## [x] Фаза 7. Давление
Читать: SPEC §7, DESIGN §6.5.
Готово, когда: soft и kamikaze работают, паузы срабатывают на подсказках и скрытой вкладке, завершённые блоки не трогаются.

## [x] Фаза 8. Итог и экспорт
Читать: SPEC §9, §10 (экспорт), DESIGN §5 Result.
Готово, когда: метрики считаются, экспорт в .txt, .md и .docx сохраняет абзацы, заголовки и списки.

## Бэклог после MVP
Проверка текста на экране Result (SPEC §15), сделано:
1. [x] Орфография: словарь убран (был nspell + dictionary-ru, чанк 3,5 МБ). Орфографию проверяет браузер, для этого режим правки «Править текст» на Result.
2. [x] Читаемость (Флеш для русского), длина предложений, повторы слов.
3. [x] Вкладка «Шаблоны»: шаблонные обороты, словесный мусор, ритм предложений, одинаковые начала, разнообразие слов.
4. [x] Подсветка найденных мест в тексте, как маркер.
5. [x] Вкладка «Сравнение»: шаблоны, перешедшие из исходника, перенесённые фразы, отметка блоков.

Правки по отзывам первых пользователей, сделано:
- [x] Result: «Новый текст» и «Пройти заново» (копия документа), шапка ведёт на Home, в Session «Мои тексты» (SPEC §9, §3.1).
- [x] Подсказки заметнее: подпись, одноразовая строка-намёк, блок «Как это работает» на Home (SPEC §3.1, §3.3).
- [x] Польза проверки видна: шаблоны исходника на Split, сводка в панели проверки, причины пустых результатов (SPEC §15.5, §15.7).
- [ ] Полнота правил по реальным ответам нейросетей (калибровка): не выполнена, тексты для калибровки не были приложены.
- [x] Убран мост к Главреду.

Браузерные проверки: `e2e/check-text.cjs` (проверка текста, сеть без единого внешнего хоста, скриншоты с `--shots`), `e2e/feedback.cjs` (правки по отзывам: навигация, подсказки, шаблоны исходника), `e2e/edit-mode.cjs` (режим правки), `e2e/perf-tabs.cjs` (время вкладок). Порядок запуска в шапке файлов.
