# SPEC: «Своими словами», MVP

## 1. Суть
Человек получил текст от нейросети и хочет, чтобы итоговый текст был его собственным: его словами, его ритмом, без ИИ-шаблонов. Запомнить весь текст сразу трудно, а короткий блок можно. Сервис ведёт человека от блока к блоку: прочитал, запомнил, текст растворился, написал своими словами. Подсказки есть, но каждая следующая «дороже» и попадает в статистику.

Принцип: сервис ничего не переписывает за человека. Автор всегда человек.

## 2. Термины
- **Документ**: исходный текст плюс всё, что пользователь по нему написал.
- **Абзац источника**: абзац исходного текста. Нужен, чтобы при экспорте восстановить абзацы.
- **Блок**: единица запоминания, не длиннее лимита (§6). Абзац источника может состоять из нескольких блоков.
- **Ключевые фразы (теги)**: 3–6 опорных фраз блока (§5).

## 3. Экраны и сценарий

### 3.1 Главная (Home)
- Большое поле «Вставь текст», зона drag&drop для .txt, .md и .docx, кнопка «Выбрать файл».
- Кнопка «Попробовать на примере» загружает текст из Приложения A.
- Список локальных документов: название (имя файла или первые 6 слов), прогресс «5 из 12», дата изменения. Действия: «Продолжить», «Переименовать», «Удалить» (с подтверждением).
- Внизу: «Сохранить копию всех документов» (JSON) и «Загрузить копию».
- Пустое состояние: одна короткая фраза о том, что делать, и поле вставки.

### 3.2 Разбивка (Split)
- Список блоков: текст, счётчик слов, ключевые фразы, подсвеченные маркером прямо в тексте блока.
- Действия над блоком: «Склеить со следующим», «Разрезать» (наведение между предложениями показывает точку разреза, клик режет), правка ключевых фраз (клик по подсветке убирает её, выделение текста мышью добавляет новую).
- Переключатель размера блоков «Короткие / Средние / Длинные» пересчитывает разбивку. Если были ручные правки, сначала спрашивает подтверждение.
- Кнопка «Начать».

### 3.3 Сессия (Session)
Состояния блока: `reading → dissolving → writing → done`.

- **reading**: блок по центру, шрифт для чтения, сверху прогресс «3 из 12». Действие «Запомнил» (Space или кнопка).
- **dissolving**: анимация растворения (DESIGN.md §6.1). Ввод в это время заблокирован, длительность не больше 1.1 с.
- **writing**: поле ввода (textarea с автовысотой) сразу получает фокус. Над ним приглушённо виден уже написанный пользователем текст: последние 2 блока, остальное доступно прокруткой. Панель подсказок проявляется при движении мыши, а горячие клавиши работают всегда.
- **Готово** (Ctrl/Cmd+Enter): блок становится `done`, следующий переходит в `reading`. Пустой блок завершить нельзя, при попытке показывается короткое сообщение под полем.
- Кнопка «Назад к предыдущему блоку» позволяет править свой текст. Done-блок открывается сразу в writing, без чтения и растворения, статус остаётся `done`. Исходник при этом не показывается, только через подсказки.
- Хранение состояний: `reading` и `dissolving` существуют только в UI. Статус блока становится `writing` в момент «Запомнил» (до анимации), поэтому при возврате после закрытия вкладки посреди растворения блок открывается в writing. Текущий блок в статусе `pending` при возврате открывается в reading.
- Выйти можно в любой момент: прогресс сохраняется автоматически. После последнего блока открывается Result.

### 3.4 Лестница подсказок
Каждая следующая ступень раскрывает больше. Ступени 1–3 включаются и выключаются переключателем, ступень 4 работает только пока её удерживают.

| # | Название | Что видит пользователь |
|---|---|---|
| 1 | **Темы** | 3–6 ключевых фраз блока чипсами-маркерами над полем ввода. Порядок как в исходнике. |
| 2 | **Скелет** | Исходный блок, где ключевые фразы видны (маркер), а остальные слова заменены плашками шириной по длине слова. Пунктуация видна. Не-ключевые слова **не попадают в DOM**. |
| 3 | **Первые буквы** | Каждое слово показано первой буквой и плашкой: «В с… м… в о…». Пунктуация видна. |
| 4 | **Подглядеть** | Полный исходник, пока удерживается кнопка или Alt+4, максимум 3 с, затем гаснет. Каждое удержание считается как 1 peek. |

Учитываем для каждого блока: максимальную открытую ступень, число открытий каждой ступени, число подглядываний и их суммарную длительность.

### 3.5 Горячие клавиши
Клавиши определяются по `KeyboardEvent.code`, чтобы не зависеть от раскладки, и всегда с `preventDefault`.
- Space: «Запомнил» (только в reading).
- Ctrl/Cmd+Enter: «Готово».
- Alt+1 / Alt+2 / Alt+3: включить или выключить ступени 1–3.
- Alt+4 (удерживать): «Подглядеть». Автоповторы `keydown` игнорируются. Подглядывание заканчивается на `keyup` Digit4 или Alt, на `blur` окна или через 3 с; одно удержание = 1 peek, повторное нажатие = новый peek.
- Esc: закрыть открытые подсказки.
- На всех сочетаниях с Alt тоже `preventDefault`, чтобы отпущенный Alt не уводил фокус в меню браузера (Windows).

**Запрещено** вешать действия на Shift (им набирают заглавные), Ctrl+Space и Cmd+Space (переключение раскладки у русскоязычных пользователей) и клавишу ` (это «ё» в русской раскладке).

## 4. Модель данных
```ts
type BlockKind = 'text' | 'heading' | 'list-item';
interface Keyphrase { start: number; end: number } // смещения в block.sourceText
interface BlockHints {
  maxLevel: 0 | 1 | 2 | 3 | 4;
  opens: { 1: number; 2: number; 3: number };
  peeks: number; peekMs: number;
}
interface Block {
  id: string; paragraphIndex: number; kind: BlockKind;
  sourceText: string; keyphrases: Keyphrase[];
  userText: string;
  status: 'pending' | 'writing' | 'done';
  hints: BlockHints;
  typedChars: number; pastedChars: number; activeMs: number;
}
interface Doc {
  id: string; title: string; source: string;
  blockSize: 'short' | 'medium' | 'long'; manualEdits: boolean;
  blocks: Block[]; currentIndex: number;
  createdAt: number; updatedAt: number; finishedAt?: number;
}
interface Settings {
  theme: 'dark' | 'light' | 'sepia';
  defaultBlockSize: 'short' | 'medium' | 'long';
  pressure: 'off' | 'soft' | 'kamikaze'; pressureDelaySec: number; // 3..30, по умолчанию 7
  allowPaste: boolean;            // по умолчанию false
  writingFont: 'serif' | 'mono';  // по умолчанию serif
}
```
Хранение: Dexie, таблицы `docs` (документ целиком одной записью) и `settings`. Автосохранение с debounce 500 мс, а также при `visibilitychange` и `beforeunload`.

## 5. Ключевые фразы (без LLM)
1. Токенизация через `Intl.Segmenter(lang, { granularity: 'word' })`, берём только `isWordLike`. Язык определяем по доле кириллицы.
2. Нормализация: нижний регистр, ё → е. Стемминг для русского: свой простой суффиксный стеммер (`stem.ts`, около 60 окончаний, от длинных к коротким, основа не короче 3 букв). Для английского: отрезать -s, -es, -ed, -ing, -ly.
3. Стоп-слова: встроенные списки ru и en, около 300 слов (`stopwords.ts`).
4. Вес слова в блоке: `tf(блок) × idf(по блокам документа)` с множителями: число, дата или процент ×2.0; заглавная буква не в начале предложения ×1.8; латиница в русском тексте ×1.5; длина от 7 букв ×1.2.
5. Фразы: соседние значимые слова сливаются во фразу до 3 слов. Предлог или союз между двумя значимыми словами допускается («рост на 20%»).
6. Количество: 3 фразы для блока до 25 слов, 4–5 для блока до 45, до 6 для более длинных. Фразы покрывают не больше 30% слов блока.
   Приоритет при конфликте: сначала минимум 3 фразы. Если они не укладываются в 30%, фразы укорачиваются до одного слова, причём остаётся **самое весомое слово фразы по score**, а не первое. Затем, если места всё ещё нет, лишние фразы сверх минимума отбрасываются с конца по весу.
   Исключение: у заголовков и коротких пунктов списка фраз столько, сколько нашлось значимых слов (0–2 допустимо).
7. Результат хранится смещениями в `sourceText`. Пользователь правит его в Split.

## 6. Разбивка на блоки
Лимит по пресету: short 25, **medium 45 (по умолчанию)**, long 70 слов. Мягкий минимум 8 слов.
1. Нормализация: `\r\n` → `\n`. Пустая строка разделяет абзацы. Строки с `#` становятся заголовками (`heading`, решётки убираются). Строки, начинающиеся с `-`, `*`, `•` или `1.`, становятся пунктами списка (`list-item`), каждый пункт отдельным блоком. Остальные одиночные `\n` внутри абзаца заменяются пробелом.
2. Если абзац не длиннее лимита, он целиком становится одним блоком.
3. Длинный абзац делим на предложения (`Intl.Segmenter`, granularity `sentence`). Число блоков n = ceil(слов / лимит), целевой размер = слов / n, резать на границе предложения, ближайшей к цели.
4. Предложение длиннее лимита режется по `;` `:` ` — ` или по запятой перед союзом (и, а, но, который, которая, которые, что, потому что, где, когда / and, but, which, because, while), выбирается место, ближайшее к середине.
5. Хвост короче минимума приклеивается к предыдущему блоку того же абзаца, если вместе получается не больше лимит × 1.3.
6. Сокращения: если «предложение» короче 3 слов и заканчивается на сокращение из списка (т.е., т.д., т.п., г., гг., см., др., ок., Dr., e.g., i.e., etc.), оно склеивается со следующим.
7. Короткая строка без точки в конце (до 8 слов), стоящая отдельным абзацем, считается заголовком.
8. Короткий отдельный абзац с конечной пунктуацией («Это важно.») остаётся отдельным блоком короче минимума: склейка через границу абзаца при автоматической разбивке не делается, чтобы не ломать `paragraphIndex`. Пользователь может склеить его в Split: «Склеить со следующим» работает и через границу абзаца, склеенный блок получает `paragraphIndex` и `kind` первого блока, и при экспорте эти абзацы сливаются в один.

Тесты: русский и английский текст, очень длинное предложение, список, заголовок, сокращения, текст из одного абзаца на 300 слов, пустой ввод.

## 7. Режим давления
- `off`, `soft`, `kamikaze`. Задержка `pressureDelaySec`, по умолчанию 7 с.
- Активностью считается любое `keydown` или `input` в поле письма, включая Backspace и стрелки.
- Таймер запускается после первого нажатия клавиши в блоке и работает только в состоянии writing.
- Таймер ставится на паузу, пока открыта подсказка 1–3 или идёт подглядывание, пока вкладка скрыта (`visibilitychange`) и пока открыто модальное окно.
- **soft**: когда бездействие превышает задержку, виньетка нарастает от 0 до 1 за 5 с. Любая активность мгновенно её сбрасывает (fade 150 мс).
- **kamikaze**: то же самое, но когда виньетка дошла до 1, каждые 400 мс исчезает последнее слово **текущего** блока с микро-анимацией. Остановка при любой активности. Завершённые блоки не трогаются никогда.
- При правке done-блока (через «Назад к предыдущему блоку») давление полностью выключено: таймер не стартует, виньетки нет, в любом режиме.
- Реализация: чистая функция или редьюсер в `lib/pressure.ts` (`tick(state, now) → { vignette, deleteWord }`), тесты на подставном времени.

## 8. Вставка и подсчёт набранного
- По умолчанию вставка в поле письма запрещена: `onPaste` и `onDrop` с `preventDefault`, под полем тихое сообщение «Вставка отключена. Включить можно в настройках».
- Если вставка разрешена, вставленные символы считаются в `pastedChars`.
- `typedChars` растёт на событиях `input` с `inputType = insertText` или `insertCompositionText`.

## 9. Итог (Result)
- Две колонки: «Исходник» и «Твой текст», блоки выровнены построчно. На мобильных вместо колонок переключатель вкладок.
- Метрики: время (сумма activeMs), слов написано, подсказки по ступеням, подглядываний, доля набранного вручную, «Свои слова».
- **«Свои слова»** = 1 − |общие 3-граммы основ| / |3-граммы основ пользователя| по всему документу, в процентах. Подпись: «Насколько формулировки отличаются от исходника».
- Экспорт: «Скопировать», .txt, .md, .docx. По умолчанию только текст пользователя. Опция «Вместе с исходником» доступна только для .md.

## 10. Импорт и экспорт
- **Импорт .txt и .md**: читаем как UTF-8. Если в тексте больше 1% символов `�`, перечитываем как windows-1251.
- **Импорт .docx**: `mammoth.extractRawText`, абзацы разделяем `\n\n`.
- Лимит 200 000 символов, при превышении показываем понятное сообщение.
- **Экспорт**: блоки с одинаковым `paragraphIndex` склеиваются через пробел, абзацы разделяются пустой строкой. Заголовки в .md выводятся как `##`, в .docx как Heading 2. Пункты списка выводятся с маркером.
- Имя файла: `<slug-названия>.<ext>`.
- **Резервная копия**: `{ app: 'svoimi', version: 1, exportedAt, documents: Doc[], settings }`. При импорте копии документы с совпадающим id предлагается заменить или пропустить.

## 11. Настройки (боковая панель)
Тема (Тёмная / Светлая / Сепия), размер блоков для новых документов, давление (Выкл / Мягкое / Камикадзе) и задержка, разрешить вставку, шрифт для письма (С засечками / Моноширинный).

## 12. Пограничные случаи
Пустой ввод; текст из одного слова; только заголовки; очень длинное слово или URL (не резать внутри); emoji; смешанный ru/en; закрытая вкладка посреди растворения (при возврате блок в writing); переполнение IndexedDB (понятная ошибка).

## 13. Критерии приёмки MVP
- [ ] Вставил текст на 600 слов, получил блоки не длиннее лимита, ни один не короче 8 слов (кроме заголовков, пунктов списка и коротких отдельных абзацев, §6 п.8).
- [ ] У каждого блока есть 3–6 ключевых фраз (у заголовков и коротких пунктов списка может быть 0–2, §5 п.6), их можно править в Split.
- [ ] Весь документ проходится одной клавиатурой.
- [ ] Растворение плавное (60 fps на M-серии Mac), с reduced motion показывается простой fade.
- [ ] Скелет не содержит не-ключевых слов в DOM.
- [ ] Перезагрузка страницы посреди сессии возвращает на тот же блок с тем же текстом.
- [ ] Kamikaze стирает только текущий блок, на подсказках таймер стоит на паузе.
- [ ] .docx импортируется, .txt, .md и .docx экспортируются с сохранением абзацев.
- [ ] Три темы, контраст текста не ниже WCAG AA.
- [ ] Ширина 360px: всё работает, ничего не выезжает за экран.

## 14. Не делаем в MVP
Аккаунты, синхронизация, бэкенд, любые LLM-вызовы, импорт PDF, детектор ИИ-паттернов, интервальные повторения, английский интерфейс (но строки уже в i18n), звуки, PWA и офлайн-установка, аналитика.

## Приложение A: пример текста
В современном мире умение эффективно управлять своим временем становится не просто полезным навыком, а настоящей необходимостью. Исследования показывают, что люди, которые планируют свой день заранее, выполняют на 25% больше задач и испытывают значительно меньше стресса.

Одним из наиболее популярных подходов является техника Pomodoro, разработанная Франческо Чирилло в конце 1980-х годов. Её суть заключается в том, чтобы работать короткими интервалами по 25 минут, разделёнными пятиминутными перерывами. Такой ритм помогает поддерживать концентрацию и предотвращает умственное истощение.

Важно отметить, что не существует универсального метода, который подойдёт абсолютно всем. Ключ к успеху — экспериментировать с разными инструментами, внимательно наблюдать за собственной продуктивностью и постепенно выстраивать систему, которая будет работать именно для вас.
