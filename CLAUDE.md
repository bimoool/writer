# Своими словами — веб-сервис пересказа текста

Рабочее название. Пользователь вставляет текст (обычно ответ нейросети). Сервис режет его на короткие блоки. Блок показывается, пользователь запоминает его, блок растворяется, и пользователь пишет его заново своими словами. В итоге получается текст, написанный человеком.

## Документы (читай только нужные разделы, а не всё подряд)
- `docs/PLAN.md`: фазы MVP, статус и ссылки на нужные разделы для каждой фазы. Начинай с него.
- `docs/SPEC.md`: продукт, сценарии, механики, алгоритмы, модель данных, критерии приёмки.
- `docs/DESIGN.md`: концепция, токены трёх тем, шрифты, экраны, анимации, тексты интерфейса.

## Стек (не менять без согласования)
Vite + React 18 + TypeScript (strict), Tailwind CSS v4 с токенами через CSS-переменные, `motion` (бывший framer-motion), Zustand, Dexie (IndexedDB), `mammoth` (импорт .docx), `docx` (экспорт .docx), Vitest.
Шрифты ставятся через пакеты `@fontsource*`, без CDN.
Нет бэкенда, авторизации, аналитики и внешних сетевых запросов в рантайме.

## Правила работы
- Строго по фазам из `docs/PLAN.md`. В конце фазы `npm run build`, `npm test` и `npm run lint` должны проходить без ошибок. Затем отметь фазу в PLAN.md, сделай коммит `phase N: <кратко>`, остановись и дай отчёт: что сделано, что проверить руками, где отошёл от спеки и почему.
- Логику (разбивка, ключевые фразы, метрики, давление, импорт и экспорт) пиши чистыми функциями в `src/lib` и покрывай unit-тестами. UI-слой держи тонким.
- Все строки интерфейса на русском и хранятся в `src/i18n/ru.ts`. Хардкод текста в компонентах запрещён.
- Цвета, шрифты, радиусы и тени берутся только из токенов (`src/styles/tokens.css`, см. DESIGN.md). Hex-значения в компонентах запрещены.
- Учитывай `prefers-reduced-motion`. Всё должно управляться с клавиатуры, фокус всегда виден. Вёрстка адаптивна до ширины 360px.
- Ничего из списка «Не делаем в MVP» (SPEC.md §14). Если сомневаешься, спроси.
- Новые зависимости сверх списка добавляй только с объяснением в отчёте.
